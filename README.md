# Hermas

Hermas is a small, safety-oriented runtime for executing verified graphs of
independent application Actions. Workflow authors use HScript, app authors
publish typed HSchema contracts, and the daemon delivers each Action without
silently retrying work that may already have happened.

This repository is the definitive pre-1.0 implementation. Its public identity
is consistently `Hermas`: the compiler is `hermas`, the daemon is `hermasd`,
the C ABI uses `hermas_*`, and source contracts use HSchema and HScript. The
legacy prototype is not compatible.

Version `0.1.0-alpha.1` targets Linux x86-64. It is experimental, but its
release gate permits no known violation of delivery, boundedness, typing, or
recovery guarantees.

## Try it

Install a C17 compiler, CMake 3.20 or newer, Rust, and Cargo, then run:

```sh
tools/quickstart.sh
```

The reproducible quickstart compiles the Grade Pipeline, creates a managed
workspace, starts three
independent Action processes and `hermasd`, executes the workflow, prints
`Mean: 80`, inspects durable history, and proves a clean restart does not
replay completed work. All processes share one private runtime workspace, so
users do not coordinate socket paths or repeat graph identity after
initialization. See
[the quickstart guide](docs/QUICKSTART.md) for installation details.

`tools/test_order_total.sh` independently exercises a second architecture
with a caller-provided integer, three unrelated contracts, different business
logic, reordered schema compilation, and its own restart proof. It prints
`Order total: 9900 cents`. The unchanged Action binaries resolve their
graph-local app, Action, and Type assignments by semantic identity.
The graph-aware runner accepts that input as `--value 10000`; callers do not
need to construct canonical scalar bytes or supply the graph path again.

## Safety model

Hermas makes uncertainty explicit:

- A delivery lost before a complete send is `NotSent`.
- A delivery lost after it may have reached an app is `Unknown`.
- `Unknown` work is never automatically replayed.
- Forward execution is closed conservatively after a restart.
- Only planner-proven safe compensation resumes.
- Graphs, values, packets, state records, resources, and concurrency are
  validated against fixed bounds.

This is a local single-host runtime. It does not claim distributed consensus,
exactly-once external side effects, remote transport, or Byzantine safety.
Read the [threat model](docs/THREAT_MODEL.md) and
[crash-recovery matrix](docs/CRASH_RECOVERY_MATRIX.md) before production-like
experiments.

## Build and verify

```sh
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check

cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

Graph fixtures used by the full C suite are generated by `hermas`; CI runs
the complete GCC and Clang ASan/UBSan matrices, Rust checks, decoder parity,
fuzz smoke tests, the quickstart, and security analysis.

To inspect execution ordering before producing an image, run
`hermas workflow plan MODULE SCHEMA...`. The report shows dependency-derived
readiness stages, bounded parallel regions, deadline scopes, and saga recovery
order. HScript source order is not a hidden scheduling guarantee.
Integrations can add `--json` to obtain the verified workflow interface,
graph-local Type IDs, and stable Action node and protocol identities without
parsing the human-readable report.

The alpha daemon executes sequential, typed-choice, deadline, saga, bounded
`all`, and bounded `each` graphs. Every parallel branch and expanded item has
its own durable delivery identity; `collect` preserves source-index order even
when items complete in a different order. The fixed arenas bound active group
executions, item count, concurrency, and payload storage before execution.

Automation can inspect durable execution facts with
`hermas_history --json --workspace DIRECTORY`. The versioned JSON Lines stream
preserves 64-bit identifiers without precision loss and ends with the exact
interrupted-execution classification.
Callers can request one lossless terminal object with
`hermas_run --json --workspace DIRECTORY EXECUTION_ID`; its versioned result
projection preserves the exact outcome, Type identities, and canonical bytes.
Automation can compare those Type IDs with the compiler plan and the durable
history without decoding graph images or constructing protocol frames.

## Design and extension points

The [master architecture](00_HERMAS_MASTER_PLAN.md) governs component
boundaries and the [philosophy](03_HERMAS_PHILOSOPHY.md) governs feature
admission. Key executable specifications include:

- [HSchema](docs/HSCHEMA.md) and [HScript](docs/HSCRIPT.md)
- [Graph image v1](docs/GRAPH_IMAGE_V1.md)
- [Protocol v1](docs/PROTOCOL_V1.md)
- [C Action app guide](docs/APP_AUTHOR_GUIDE.md)
- [Runtime workspace](docs/WORKSPACE.md)
- [Workspace manifest v1](docs/WORKSPACE_MANIFEST_V1.md)
- [History JSON Lines v2](docs/HISTORY_JSON_V2.md)
- [Compatibility policy](docs/COMPATIBILITY.md)

Community growth should primarily add Actions, bindings, diagnostics, test
corpora, and tools. Runtime-semantic changes require a specification,
bounded-resource analysis, and executable invariants. See the
[feature-admission guide](docs/FEATURE_ADMISSION.md).
